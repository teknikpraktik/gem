# REGIONAL_SEK signal monitor (PWA)

Next.js (App Router, TypeScript) app that shows the monthly **REGIONAL_SEK** signal
(Avanza USA / Avanza Europa / Avanza Emerging Markets / Avanza Ränta Kort), why it
was chosen, data quality, history, backtests and research models.
It never trades and never shows an old signal as current.

## Architecture

```
lib/engine/       rule engine: TypeScript port of research/src/gem/live.py
                  (conformance-tested against fixtures generated by the Python reference)
lib/providers/    NavProvider / YieldProvider interfaces + Avanza (UNDOCUMENTED_ENDPOINT) and Riksbank SWEA
lib/pipeline.ts   monthly job: period -> fetch -> validate -> engine -> classify -> immutable snapshot
lib/status.ts     read-time status: VALID | WAITING_FOR_DATA | NO_SIGNAL | DATA_ERROR | STALE_DATA
lib/store/        SignalStore: Postgres (db/schema.sql) or in-memory/read-only bootstrap
app/              pages (/, /history, /backtest, /research) and API routes - no investment logic
data/*.json       static exports of the research pipeline (scripts: research/scripts/export_app_data.py)
```

The frontend only displays stored snapshots; it never computes a signal.

## API

| Route | |
|---|---|
| `GET /api/signal` | current state (status, signal for the expected period, last valid signal kept separate, latest NAVs) |
| `GET /api/history` | signal history (live snapshots override the research backfill) |
| `GET /api/status` | store, last attempts, providers |
| `GET /api/backtest` | static backtest export |
| `GET/POST /api/cron/monthly-signal` | monthly job; requires `Authorization: Bearer $CRON_SECRET` |

There is no public write endpoint.

## Monthly job

`vercel.json` calls `/api/cron/monthly-signal` at 05:15, 10:15 and 16:15 UTC on days 1–10.
Each call is idempotent: once the month's final snapshot (VALID or NO_SIGNAL) exists it
returns `ALREADY_FINAL` without fetching data. Missing month-end NAV → `WAITING_FOR_DATA`
(logged, retried next run); provider/format failure → `DATA_ERROR`. Snapshots are
immutable (unique strategy+period+version, DB trigger blocks UPDATE/DELETE).

## Local development

```bash

```

## Deploy to Vercel (not done yet)

1. Vercel → *Add New Project* → import `teknikpraktik/gem`; **Root Directory = `web`** (framework Next.js, defaults otherwise).
2. Storage → *Marketplace* → **Neon** Postgres, connect to the project (sets `DATABASE_URL`).
3. Settings → Environment Variables (Production):
   - `CRON_SECRET` – random, ≥ 16 chars (`openssl rand -hex 32`)
   - `RIKSBANK_API_KEY` – optional
   - (`FRED_API_KEY` is **not** needed here; it is a GitHub Actions secret for research only.)
4. Create the schema once: `DATABASE_URL=... npm run db:migrate` (idempotent; runs `db/schema.sql`).
5. Deploy. Cron jobs are registered from `vercel.json` on production deployments.
6. Optional first run: `curl -H "Authorization: Bearer $CRON_SECRET" https://<app>/api/cron/monthly-signal`.

Notes: on the Hobby plan each cron job may run at most once per day and timing is
approximate within the hour – the three daily entries satisfy that; if your plan rejects
three entries, keep one (e.g. `15 10 1-10 * *`). Function region near Stockholm (e.g. `arn1`)
is optional.

## Data sources

- NAV: avanza.se fund-guide JSON – **UNDOCUMENTED_ENDPOINT**, replaceable behind `NavProvider`.
  Every response is validated (ISIN/currency, daily spacing, no future dates, no >25 % jumps).
- Cash hurdle: Riksbank SWEA `SETB3MBENCH` (official API).
- Backtest/research numbers: static exports from the research workflow.
